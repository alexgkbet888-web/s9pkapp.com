OTP and login recovery routing

Updated: 2026-07-18

Route split for OTP, login, and registration failures to reduce support loops.

Direct update

  • Separate three failure branches: OTP/login/registration
  • Set network and permission checks first
  • Route users to right reset or register path

Execution flow

  1. Confirm issue branch first
  2. Offer short retry and cache clear sequence
  3. Guide users from OTP branch to register or login pages

FAQ

What if OTP is delayed?

Retry after network check, device settings, and SMS queue refresh.

Is account lock separate from password issue?

Yes. Show password and account lock steps separately.

Should all recovery issues use one form?

No. Keep separate pages for login, register and OTP branches.
